## Firmware review: Jet 75 II 1.16

Image SHA-256 `update_jet75II…bin` is recorded in `acquisition.json`. It is
WCH QingKe RISC-V code (XW compressed byte/halfword instructions; disassembled
with LLVM 21 `--mattr=+m,+a,+c,+f,+xwchc`). **Load base 0x5000** (the opcode
jump table resolves only there, same as MAD 68 Pro R). bcdDevice 0x0116.
Build stamp "Aug 28 2025" "10:45:06".

USB: interface 0 boot keyboard (62-byte descriptor), interface 1 M HUB channel
(Generic Desktop/0, 64-byte IN/OUT, no report ID), interface 2 NKRO (163).

Command transport (parser at 0x5F84): `55` framing, length ≤ 56, optional XOR,
checksum = sum of bytes 4..7+length; reply marked `AA` (bad checksum `AB`),
checksum recomputed by the common epilogue (0x62DA). Same as Mix87 III, so the
Mix87 framing helpers are reused. The opcode table at 0x13840 is complete:
`01..0E, A0..A9, B0, B1, DD, DE, EE, F1, F2`; unknown opcodes reply "unkw".

| Opcode | Handler | Meaning established |
| --- | --- | --- |
| 03 | 0x692C | version 0x0116 + "Aug 28 2025,10:45:06" (length 22) |
| 04 | 0x6900 | read flash 0x20200 + offset (profile base) |
| 05 | 0x68D4 | read flash 0x20100 + offset (256 settings bytes, 4 profiles × 64) |
| 06 | 0x5ED8 | write ≤256 bytes to flash 0x20100 + offset, reload the active profile |
| DE / DD | 0x644E / 0x6492 | read / write a RAM block (not used) |

There is **no memory-read command** (Mix87 uses `E0`), so code fingerprints
cannot be hashed on the device.

**Owner decision (2026-10-02): no firmware-version binding.** A version list
would break support on every vendor update. Admission requires only a valid
M HUB `03` reply; the version is logged (`jet75.firmware_version`, and
`jet75.firmware_unreviewed` when it is not 0x0116). Safety comes from the data:
the profile base and the AA BB settings layout are checked before the single
one-bit write, all 256 settings bytes are read back after it, and A0 reports
must carry a known key and a switch maximum of 200..600 (0.01 mm; 1.16 uses
331/341/351). A firmware that changes the protocol therefore fails closed: no
write, or the session stops and the flag is cleaned up. Residual risk: a future
firmware could reuse the same bit for something else; not detectable offline.

Analog path (identical design to Ace 60 / Mix87 III):

- Builder 0xB76E emits `A0`: bytes 1..3 factory descriptor (table 0x1629C),
  bytes 6..7 processed travel (≤ 9 → 0, ≥ max−5 → max), bytes 14..15 the switch
  maximum (table 0x13FEC: 341 for types 0..7, 351, 331).
- Service 0xB8EE runs only while **profile byte 7 bit 3** (RAM 0x200053D7) is
  set; every 10 ticks after 24 quiet passes (any host command resets them); one
  changed key per pass, round-robin over 80 slots, optional full sweep.
- Bit 3 of byte 7 is read only by this service (other code tests bits 1 and 2),
  so the flag does not touch scanning or typing (static evidence, not a typing test).
- Slots 0..79: 79 HID keys + Fn (`F0 FF 01`), no duplicates; identical to the
  official M HUB Jet75 layout (80 keys).
- Boot (0x94B4): base `{current, count, profile table}` from 0x20200; profile
  config 64 bytes from 0x20100 + 64·profile into RAM 0x200053D0; magic AA BB
  at bytes 2..3 (otherwise defaults from 0x16E98: byte 7 = 0x06, flag off).
- `A1` is sent on a profile switch, `A2`/`A3` after keymap writes.

**Restriction found (new, not modelled for Mix87):** after an `06` write the
firmware reboots the keyboard when byte 0 bit 0 of the settings area (0x20100)
is set. The first boot after flashing (marker at 0x08004C00 ≠ 41E4:211B) and
the factory-reset key action set that bit; no code clears it. The write still
lands, but there is no reply and USB reconnects.

## Implementation

- `mchose_jet75_protocol.h`: reads (04/05), info check, flag write (06),
  decode, `ChangeFlag` with one write attempt, full readback and a
  `Rebooting` result when the reboot bit is set.
- `mchose_jet75_backend.cpp`, protocol 29 `MchoseJet75`: same lifecycle as
  Mix87 III (owner decision 2026-09-27): enable at start/resume, disable at
  pause/exit, at most one automatic enable per worker generation. After a
  reboot the next session finds the flag on and owns its cleanup. A1/A2/A3/AA/AB
  end the session (pause/resume re-admits). No calibration commands.
- Layout: `build_supported_gap_layouts.py` source `mhub-jet75` → report
  `mchose_jet_75_ii_ansi` (80 keys) → catalog token `JET75II-41E4-211A`,
  automatic selection after admission. `--extract/--write-new` now create
  only missing files and verify existing ones byte for byte.
- Yellow notice: `FrozenModel::MchoseJet75` (33554432), title
  "MCHOSE Jet 75 II: hardware testing incomplete"; notice group protocol 29.

## Tester log `message (7).txt` (2026-10-02 06:51 UTC, build with this backend)

- Firmware reported **0x0117 (1.17)**: the version-independent admission was
  necessary; under the earlier exact-1.16 rule nothing would have run.
- Enable transaction Verified (`auto_enable_result=0`), profile 0, layout and
  readback checks passed on 1.17.
- 62 ms later a system-wide `device.change` arrived (startup; most likely our
  own virtual gamepad). The backend ended any session on ANY device-change
  notification, so it disabled the flag (`cleanup_mode_result=0`) and, by the
  one-enable-per-generation rule, refused to enable again
  (`auto_enable_retry_blocked`). Result: no analog. Keyboard and protocol fine.
- Root cause fixed in BOTH Mix87 III and Jet 75 II backends: device-change
  notifications only wake the idle worker; a healthy session continues. Removal
  of the keyboard fails the next read (`stream_failed`) and ends the session.
  Mix87 had the same latent bug (it likely escaped only because its slower hash
  admission finished after the startup notification; a USB device plugged in
  during play would have killed analog until pause/resume).
- Session tests now send a notification mid-stream and require the stream to
  continue; the previous Mix87 backend fails this test, the fixed one passes.
- Build and diagnostics gate PASS. EXE SHA-256 prefix 015a6881f9216b7d.
  Backup: `.local/backups/mchose_mix87_backend.cpp.before-devchange-2026-10-02`.
